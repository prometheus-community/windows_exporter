## Flags

### `--collector.mssql.enabled`

Comma-separated list of MSSQL WMI classes to use. Supported values are `accessmethods`, `availreplica`, `bufman`, `databases`, `dbreplica`, `genstats`, `info`, `locks`, `memmgr`, `sqlstats`, `sqlerrors`, `transactions`, and `waitstats`. Defaults to all, if not specified.

## Useful queries

### Database file size
This collector retrieves the two values (data file and log file) and sums the total in PromQL to give the Database file size.

```
windows_mssql_databases_data_files_size_bytes{database='DatabaseName',instance='host:9182'} + windows_mssql_databases_log_files_size_bytes{database='DatabaseName',instance='host:9182'}

```

### Buffer Cache Hit Ratio

When you read the counter in perfmon you will get the the percentage pages found in the buffer cache. This percentage is calculated internally based on the total number of cache hits divided by the total number of cache lookups over the last few thousand page accesses.
This collector retrieves the two internal values separately. In order to calculate the Buffer Cache Hit Ratio in PromQL.

```
windows_mssql_bufman_buffer_cache_hits{instance="host:9182", mssql_instance="MSSQLSERVER"} /
windows_mssql_bufman_buffer_cache_lookups{instance="host:9182", mssql_instance="MSSQLSERVER"}
```

SQL Server refreshes both values every few seconds with the hits and lookups of the last interval, so they are gauges and need no `rate()`.
The same applies to `databases_log_cache_hits` and `databases_log_cache_lookups`.

### Ratios and averages of running totals

The Worktables From Cache Ratio, Average Wait Time (ms), XTP Controller DLC Latency/Fetch and Update conflict ratio counters are running totals.
Divide the rates of numerator and base:

```
# Worktables From Cache Ratio
rate(windows_mssql_accessmethods_worktables_from_cache_hits_total[5m]) / rate(windows_mssql_accessmethods_worktables_from_cache_lookups_total[5m])

# Average lock wait time in seconds
rate(windows_mssql_locks_wait_time_seconds_total[5m]) / rate(windows_mssql_locks_count_total[5m])

# Average XTP controller DLC latency per fetch in seconds
rate(windows_mssql_databases_xtp_controller_dlc_fetch_latency_seconds_total[5m]) / rate(windows_mssql_databases_xtp_controller_dlc_fetches_total[5m])

# Update conflict ratio
rate(windows_mssql_transactions_update_conflicts_total[5m]) / rate(windows_mssql_transactions_update_snapshot_transactions_total[5m])
```

### Wait statistics

Each `windows_mssql_waitstats_*` metric is a wait type. The `item` label names the statistic: `Average wait time (ms)`, `Cumulative wait time (ms) per second`, `Waits in progress` and `Waits started per second`.
SQL Server computes them over its most recent sampling interval, so they are gauges. Values of the `(ms)` items are in milliseconds.

## Alerting examples

```
groups:
- name: database_alerts
  rules:
  - alert: DatabaseSizeExceeded
    expr: windows_mssql_databases_data_files_size_bytes{database='DatabaseName',instance='host:9182'} + windows_mssql_databases_log_files_size_bytes{database='DatabaseName',instance='host:9182'} > 1e10  # 10 GB in bytes
    for: 5m  # Trigger the alert if the condition persists for 5 mins
    labels:
      severity: critical
    annotations:
      summary: "SQl EXpress Database size exceeded 10GB"
      description: "The database size has grown larger than 10GB. Instance: {{ $labels.instance }}"

```
